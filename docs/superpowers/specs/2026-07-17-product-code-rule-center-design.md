# 产品编码规则中心设计

## 目标

把当前单一的“供应商编码 + 流水号”规则升级为正式版可配置规则中心，支持管理员自由组合规则段，并让产品创建页、规则预览、后端生成逻辑全部使用同一套规则口径。

## 现状

- 当前规则只有 `mode = supplier_sequence` 与 `serialLength`
- 前端规则页只能改流水位数
- 产品创建页只能展示“供应商编码 + 流水号”的灰色提示
- 后端自动生成采购编码时，固定按 `供应商编码 + 流水号` 生成

## 本次范围

本次只增强采购编码自动生成规则，不改销售编码逻辑。

### 支持的规则段

- 固定前缀 `prefix`
- 供应商编码 `supplier_code`
- 分类编码 `category_code`
- 年月 `year_month`
- 流水号 `serial`

### 规则约束

- 流水号必选
- 除流水号外，至少还要启用一个业务段
- 流水号固定在最后
- 允许管理员自由勾选前缀、供应商编码、分类编码、年月
- 前缀支持手工输入
- 流水号支持位数配置
- 流水范围支持：
  - `global`：全局流水
  - `per_supplier`：按供应商独立流水

## 页面设计

### 规则中心页

规则中心页新增以下内容：

- 当前启用规则摘要
- 规则段配置区
- 流水规则区
- 实时预览区
- 使用提示区
- 注意事项区

### 产品创建页

采购编码切到自动生成时，显示：

- 当前规则摘要
- 生成前提
- 示例编码
- 缺失字段提示

若规则所需字段不完整：

- 仍允许用户看到自动生成模式
- 但输入框显示灰色不可手填状态
- 页面明确提示缺失原因，例如“需先选择供应商”“需先填写产品分类”

## 数据结构

统一在共享层定义 `ProductCodeRule`：

- `strategy`: `composed_segments`
- `serialLength`
- `serialScope`
- `segments`
- `updatedAt`
- `updatedBy`

每个段包括：

- `key`
- `enabled`
- `order`
- `value`（仅前缀使用）
- `format`（年月使用）

## 生成逻辑

### 分类编码映射

先按当前分类枚举做固定映射：

- `electronics` -> `ELEC`
- `consumables` -> `CONS`
- `service` -> `SERV`

### 流水统计

- `serialScope = global` 时，按全部商品数计算下一号
- `serialScope = per_supplier` 且启用了供应商编码段时，按相同供应商统计
- `serialScope = per_supplier` 但未启用供应商编码段时，不允许保存该规则

### 字段缺失处理

后端生成采购编码时：

- 缺供应商编码且规则启用了供应商段：报错
- 缺分类且规则启用了分类段：报错
- 其余段按规则拼接

## 兼容策略

- 旧规则文件读取后自动兼容为：
  - 启用供应商编码段
  - 启用流水号段
  - 流水位数沿用旧值
  - `serialScope = per_supplier`
- 历史商品编码不回写
- 手工采购编码不受影响

## 非目标

- 不做多套规则并存
- 不做历史编码批量重算
- 不做复杂分隔符编辑器
- 不做不同商品分类使用不同规则
