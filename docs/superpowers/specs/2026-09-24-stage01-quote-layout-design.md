# 第 01 段：需求/报价列表与详情

依据已确认需求 R05-01～R05-07。此次仅修改既有需求/报价阅读场景和动作区排版，不改变审批/转单条件。

## 决策

| 决策 | 实现 |
| --- | --- |
| Q1 列表明细来源 | 从单据自己的 `items` 快照返回 `lineNo/productName/quantity/unit`，runtime / Prisma 共用投影。不读取产品库当前名称/价格，不暴露采购字段。 |
| Q2 一单一行 | 八列依次为单号、类型、状态、客户、产品、数量、创建人、操作。多产品按原行顺序逐条显示，产品与数量都标注同一明细行号，行间加细分隔线；产品名固定行高截断，鼠标悬停或点击产品链接进入详情可查看全文；完整快照不截断。 |
| Q3 状态 | 共用 web 展示函数，覆盖 shared 中全部 QUOTE_STATUSES 和已有旧状态。列表、筛选、详情、版本/反馈历史与报价审计的 status 变更显示英文 + 中文；未知状态保留原值并标记未知状态。接口状态值不变。 |
| Q4 详情 | 现有附件位置已在明细前，保持；版本移到明细后。需求单详情和草稿编辑显示“附件、需求明细”，报价单显示“报价附件、报价明细”。老板审批需求单与下方转单并入同一动作栏目，只留一处当前流程说明，保留角色和状态判定。 |
| Q5 数据兼容 | 历史无明细的演示列表记录显示“-”，不捏造产品/数量。新增可选列表明细字段，无数据库迁移、无历史写入。 |

## 验收

销售查看自己单据，老板查看待审批需求；列表能逐项匹配多产品数量，长名称不撑开页面；状态筛选、详情与历史均为双语；附件在明细前、版本在明细后；审批与转单同一区域且原权限不变。接口新增字段不得带出供应商/采购价。

## 边界

本段不宣称完成 R10 的报价流程变更、R02 的新权限或 R19 的全系统防重复。复用当前动作，不新增写入入口。当前动作的既有测试作为回归检查；后续段按完整范围交付相应规则。
