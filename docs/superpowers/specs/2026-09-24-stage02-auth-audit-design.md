# 第 02 段：会话、审计权限与验收入口设计

**基线：** `v1.2.0`，承接已验收的第 01 段提交 `5250809`。依据 `docs/requirements/v1.2.0-followups.md` §2，范围 R02-01～R02-04。

## 业务结果

1. 未登录浏览器打开任意 `/app/*` 业务链接，只能进入登录页；URL 中的 `role`、`user`、`access` 不是身份凭据。
2. 登录会话由 API 签发并校验，包含过期时间；刷新业务页会重新获取当前用户、角色及角色权限。账号停用、会话过期则回到登录页。
3. `audit.view` 是独立的“审计查看”动作权限。默认管理员拥有，其他角色默认没有；管理员可以在既有角色权限页授权。它同时控制集中审计中心、各业务页面的审计区及审计接口。既有 `audit` 模块值不再授予审计查看。
4. 导航及首页移除“全链路验收中心”，原 `/app/mvp` 链接重定向至正式首页，不删除其他业务操作。

## 决策

| 编号 | 决策 | 原因 |
| --- | --- | --- |
| Q1 | API 在登录成功时签发带过期时间的 HMAC 会话票据，Web 仅在 HttpOnly Cookie 中保存票据。 | 现有明文 JSON Cookie 可伪造；复用现有两侧共享的正式会话密钥，不增加表或清库。 |
| Q2 | Web 中间件对每次业务页请求调用 API 会话校验接口，取得当前权限后向页面内部传递；不接受 URL/Referer 自报身份。 | 满足刷新即生效、停用即失效，并尽量保留当前页面组件的 session 入参。 |
| Q3 | API 对受保护接口仅接受有效签名会话，并用签名中的身份覆盖自报 header；测试环境的旧 header 兼容只用于既有单元测试。 | 页面与接口均防身份伪造；避免一次改动所有领域控制器的取参方式。 |
| Q4 | `audit.view` 属于动作权限。管理员始终拥有基础审计查看权；授权其他角色时不必额外勾选“日志中心”模块。 | 需求要求一项权限控制集中与单据审计，避免双开关冲突。 |
| Q5 | 不新增 Prisma 字段或迁移：角色权限已存 `actions` JSON；runtime 同结构。 | 两种模式都能原位保存，历史单据及日志保持不变。 |

## 验收重点

- 浏览器 A 登录管理员，浏览器 B 无 Cookie 访问 A 的完整业务链接，被送去登录；篡改 A 地址栏中的角色参数不会变成其他人。
- 管理员给销售角色打开审计查看，销售刷新后看到日志入口及单据审计，关闭再刷新即消失；直接调用审计 API 按同一权限返回允许或拒绝。
- 管理员停用账号后，旧 Cookie 在下一次业务请求失效；runtime 与 Prisma 路径都只读取各自用户和角色权限数据。
- 登录、审批等原有业务操作仍沿用既有页面和接口；本段不扩展跨单据防重复提交，留待第 03 段。
