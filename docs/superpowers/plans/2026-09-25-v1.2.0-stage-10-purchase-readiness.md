# v1.2.0 第 10 段：采购提交与交期提醒实施计划

依据：`docs/requirements/v1.2.0-followups.md` 第 11、15、20 条；总计划 `2026-09-24-v1.2.0-followups-stages.md`。范围仅 R11-01～03、R15-02～06、R20-02。

## 交付边界

- 新采购单默认标题由来源销售单号、按明细顺序的产品名和供应商名组成。明细名过长时在生成标题时缩略并保存缩略结果；采购负责人提交审核前可改标题。历史单据无标题时保留原有展示，不批量回填。
- 采购详情去掉重复的客户订单号和门店卡片；供应商卡片只展示值。关联发货批次已录入货代/入仓号时靠前展示，数据仍来自发货批次。
- 审批通过且尚未发货的采购单，负责人可修改工厂预计交货时间；接口校验角色、负责人、当前状态和日期，runtime/Prisma 均保存并记录审计。同日重复修改不产生新记录。
- 工厂预计交货日期前三天起，尚未全部发货的采购单产生对应负责人待办；日期变更、发货或状态变化后随当前单据重新计算，不回填历史待办。

## 步骤与验证

- [x] 测试标题生成、提交修改、列表/详情展示及保存模式；实现采购记录字段和页面输入。验证采购员可改本人草稿标题，非负责人及提交后不能改，历史单据仍按旧标题展示。
  > runtime 测试覆盖生成、供应商变更时默认标题同步、保存、列表和重复提交；详情与列表页面测试通过。历史采购单未回填标题，仍沿用旧列表文案。
- [x] 测试交期修改接口的状态/权限/日期/重复请求和两种存储；实现详情页编辑与成功刷新。验证审批前、已发货和他人请求均被拒绝。
  > runtime 与 Prisma 测试验证订单及明细日期同步；前端只给审批通过、未发货的负责人显示入口，接口再校验负责人和状态。同日重复修改被拒绝。
- [x] 测试提前三天待办的日期边界、归属、部分/全部发货及交期变更；实现基于当前采购数据计算待办。验证过期和已完成单据不会产生错误待办。
  > 待办测试覆盖三天边界、变更后消失、他人不可见、部分发货继续提醒和全部发货停止提醒；逾期未全部发货继续提醒。
- [x] 测试详情字段去重、货代与入仓号有值才展示；运行 `make ci`，尝试页面关键操作，记录未能实测部分。完成后停止等待验收。
  > `make ci` 全绿。Codex 内置浏览器只读打开本地采购列表与详情，确认旧单据无标题回填、重复字段消失；当前可用的旧单据不符合本段新建和交期编辑场景，未在页面提交真实单据或修改业务数据。

存储：新增字段位于现有采购单 JSON payload，不改 Prisma 表结构，无清库或历史回填。
