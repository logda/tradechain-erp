# 第 03 段写入防重复实施计划

**Goal:** 完成 R19-01～R19-05 的全系统保存、提交、审批、转单、发货及待办处理防重复。

**Architecture:** Web 端同一提交意图使用稳定请求标识并锁定按钮；API 校验标识、操作者和请求摘要，用 runtime JSON / Prisma 唯一记录返回已完成结果，业务状态流转在并发下只允许一次有效推进。

**Spec:** `docs/superpowers/specs/2026-09-24-stage03-idempotency-design.md`

## 步骤

- [x] 1. 写红测覆盖 API 同标识并发、成功重放、失败重试及请求冲突；实现 runtime / Prisma 记录与迁移，核对授权后才触发拦截。

> 实际结果：全局拦截器在业务守卫通过后执行；runtime 文件与 Prisma 唯一记录均能重放成功结果，失败释放占用，变更请求返回冲突。新增 `20260924000000_idempotency_records` 增量迁移；HTTP 与真实业务建单测试覆盖重复请求只创建一次。

- [x] 2. 写红测覆盖共用按钮成功锁定、失败重试、二次点击；实现统一页面反馈与标识传递。

> 实际结果：共用操作表单与自定义表单使用同步提交锁和稳定请求标识；成功锁定，失败沿用标识重试，修改内容后换标识。新增钩子与表单回归测试。

- [x] 3. 逐个核对正式业务表单和 Server Action：新建、草稿、提交、审批、转单、发货、待办入口均传标识并在成功后锁定，补必要业务测试。

> 实际结果：核对现有页面的写入入口，覆盖通用流程按钮、报价/销售/采购/发货/售后新建与草稿、询价和样品操作，以及用户和主数据保存。报价、销售自动保存与手动提交顺序化，避免未取得草稿编号时再次建单。待办指向这些同一业务处理入口。

- [x] 4. 检查关键流程的状态前置条件与并发写入，补 runtime/Prisma 回归测试，保证来源、目标、待办在重复操作后只有一次变化。

> 实际结果：同单据不同请求标识按资源串行；修补发货批次状态流转以服务端实际状态校验，并在 Prisma 写入时按预期状态更新。回执重复发送被拒绝；runtime 与 Prisma 模拟测试覆盖重复状态操作。待办由单据状态派生，重放不重复推进状态。

- [x] 5. 运行定向测试和 `make ci`，使用隔离数据实际验证页面关键操作，记录结果并停在本段等待验收。

> 实际结果：pnpm 9.12.0 执行 `make ci` 通过，共 914 个测试（shared 41、web 361、api 512）。隔离 runtime 页面使用管理员双击新增用户只生成一条记录，成功后按钮禁用；重复用户名报错后可修改并成功重试。Prisma schema 生成与模拟持久化测试通过；本机未连接 MySQL，迁移未在真实数据库执行。

不发布、部署、合并、打标签；保留用户的 `docs/requirements/` 未跟踪资料。
