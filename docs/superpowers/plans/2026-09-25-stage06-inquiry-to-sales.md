# 第 06 段：询价到销售单实施计划

依据：`docs/requirements/v1.2.0-followups.md` §10、§14.3，及按模块 Excel 中 R10-01～R10-06、R14-03。第 05 段已由用户验收。只处理本段，不提前实施低于成本提醒（第 08 段）。

## 验收边界

- R10-01：采购提交询价后锁定供应商报价；老板可驳回回待询价，待办随状态切换；前端不显示编辑入口，接口拒绝旧状态提交。
- R10-02：需求转报价后保留原记录，列表隐藏已转换需求；报价详情底部直接展示来源需求的历史快照。
- R10-03：每家供应商可填写打样信息，采购和老板可见全部；销售只见选定供应商的打样信息，不能经报价 API 得到其他供应商的内容。
- R10-04：老板拥有报价后续操作入口及对应接口权限，包括客户反馈和转销售单。
- R10-05、R10-06、R14-03：询价确认时新建或复用产品均写入本次采购价、装箱数、外箱尺寸与毛重；报价与销售单保留当次快照，产品库及时读取新值；销售单另设三个字段，不改数量/件及每件数量。

## 顺序与检查

- [x] 先补询价状态、驳回、打样信息与脱敏的 API 测试，确认旧实现失败；实现 runtime/Prisma 状态写入、审计与权限；跑询价定向测试。

> 实际结果：runtime 测试先复现待老板确认仍可改供应商问题，修复后覆盖冻结、驳回、重复驳回、重新提交和打样信息保存。Prisma 使用现有 `BusinessDocument.payload` 与审计表，无 schema 变更。

- [x] 补需求来源快照、列表隐藏及老板操作权限测试；实现 API 和页面；跑报价定向测试。

> 实际结果：报价保存来源需求快照；已转换需求从列表隐藏，详情仍可追溯；老板可记录客户反馈和转销售单，接口用角色及任一动作权限共同校验。

- [x] 补产品复用更新和装箱信息跨单据测试；实现产品、报价、销售单及页面字段；跑产品/销售单定向测试。

> 实际结果：新建/复用产品时同步采购价和外箱资料；报价与销售单保存各自快照，销售单详情和草稿编辑均保留独立外箱字段。runtime 全链路与 Prisma 产品更新测试通过。

- [x] 检查待办归属与节点消失、重复请求、历史记录不被主数据更新改写；跑相关测试和 `make ci`。

> 实际结果：驳回后待老板确认询价待办按现有状态过滤立即消失；重复驳回及已锁定状态的重复比价被拒绝；产品库后续更新不改历史报价快照。采购负责人专属待办仍按第 09/12 段的负责人分配与全流程待办需求实施。本段 `make ci` 通过（API 530、Web 369、shared 全部测试通过）。

- [x] 在可用的本地浏览器按采购→老板→销售角色验证主要页面操作，记录未能验证的环境限制；只提交本段文件，汇报后等待用户验收。

> 实际结果：Codex 内置浏览器连接隔离 runtime（3200/3201），验证询价锁定、老板驳回、采购重填打样/装箱、重新提交、老板确认及销售单新建页外箱字段。完整的新需求转报价及销售角色脱敏由自动化全链路测试验证，未在浏览器重复建新需求单。隔离环境与用户正在使用的 3100 端口分开。

数据方案：询价、报价、销售单现存于 runtime JSON 或 Prisma `BusinessDocument.payload`；本段在文档 payload 上增量保存快照字段，产品主数据只使用已有 Product 列，因此无需清库或 schema 迁移。既有单据不回填。
