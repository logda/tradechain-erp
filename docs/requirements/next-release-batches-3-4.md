## 3. 详细需求

### 第 3 批：回单、发货异常、日期和出库好操作

#### M06：回单上传真实文件

**修改状态：未修改。**

- 要改什么：上传回单时选择实际文件，使用已有附件能力；不能用示例链接登记上传成功。
- 验收：没有文件不能标为上传成功；保存后能打开对应的真实回单。

#### M07：明确“发送回单”到底做了什么

**修改状态：未修改。**

- 要改什么：现有功能只是登记线下已发送，按钮改为“登记回单已发送”，记录发送对象、时间和方式。将来接入真正的发送渠道时，才使用直接发送的表述。
- 验收：用户不会以为点击后系统已经向客户发送文件；能查到线下发送登记。

#### M19：发货异常要有处理完成的出口

**修改状态：未修改。业务口径：异常与运输状态的关系待确认。**

- 要改什么：补齐异常类型、处理人、处理结果和“处理完成”入口，完成后可继续运输流程并结束对应待办。
- 待确认：异常作为独立标记，还是替代运输状态；若替代，如何恢复到正确节点。
- 验收：能完成“标记异常→处理→恢复跟踪”的完整过程，不会长期卡在异常待办。

#### M20：发货日期和预计到货时间可以更新

**修改状态：未修改。**

- 要改什么：登记货代发运时确认实际发运日期；运输过程中可维护预计到货时间、货代资料和备注，并保留变更记录。
- 验收：不用在新建批次时猜未来日期；改期后列表、详情和提醒同步更新。

#### M21：出库选择实际仓库和库位

**修改状态：未修改。业务口径：工厂直发是否经过自有库存待确认。**

- 要改什么：生成出库草稿前选择实际仓库、库位，并显示可用库存；已有明确来源时可预填，不能固定使用仓库 1、库位 11。
- 待确认：工厂直发货代与自有仓发货分别采用什么库存流程，不能为了统一页面虚构入库、出库。
- 验收：同一产品存在两个仓库时，按用户选定的实际仓位出库；生成草稿与确认扣库存的动作清楚区分。

### 第 4 批：单据关联、售后和整单状态正确

#### M09：售后选择实际产品、数量和类型

**修改状态：未修改。**

- 要改什么：从发货单生成售后时打开预填表单，选择受影响产品、数量、类型并填写原因；带入可售后数量，不能默认整批破损。
- 验收：一批货只有一个产品的部分数量有问题时，能准确登记该部分，不扩大到整批。

#### M16：新建发货和售后不用填写内部 ID

**修改状态：未修改。**

- 要改什么：按业务单号、客户或产品搜索选择；从单据详情进入时带入关联。选定销售单后，只能选择其对应采购单和发货批次。
- 验收：用户不用查看网址找 ID；不能拼出不属于同一业务链的关联组合。

#### M17：售后的客户、供应商从来源带入

**修改状态：未修改。**

- 要改什么：根据来源单据带入真实客户、供应商和产品；改变来源后同步更新。缺少合法关联时明确提示补选，禁止默认选列表第一条。
- 验收：从不同发货批次进入售后，客户和供应商始终与来源一致。

#### M22：部分完成不能把整单标成完成

**修改状态：未修改。业务口径：部分完成、全部完成、无须处理的展示规则待确认。**

- 要改什么：根据所有有效售后单和回单汇总整单状态；一张子单完成不能覆盖其他未完成子单。销售财务复核与售后费用确认分开。
- 验收：两张售后只关闭一张，整单仍显示有售后处理中；两个批次只登记一份回单发送，不能显示全部发送；售后确认不代替销售收款核对。
- 展示建议：没有发生售后时显示“无售后”，不要显示“售后未通过”；不改变已确认的内部交付收口规则。
