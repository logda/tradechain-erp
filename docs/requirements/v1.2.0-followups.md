# ERP v1.2.0 后续需求记录

当前阶段：逐条收集并确认业务需求。用户说“停止”前，只记录需求与业务口径，不实施代码修改。

## 1. 供应商合作分类

- 往来单位库中的供应商区分为“已合作供应商”和“未合作供应商”。
- 新供应商默认为“未合作”。采购单首次发货时，对应供应商变为“已合作”；部分发货也算发货。
- 老板可在往来单位库手动修改合作分类，也可编辑往来单位的其他资料。若老板手动改为“未合作”，该供应商后续再次发货时，系统仍自动改回“已合作”。
- 升级前已有的发货记录不回填合作分类；只从升级后的新发货开始自动变更。
- 采购单仅手填供应商名称、未关联往来单位时，发货后要在往来单位库自动创建“已合作”供应商档案。若已有名称完全相同的供应商档案，则复用该档案并改为“已合作”，不重复创建。

## 4. 往来单位客户与供应商的新增、归属及可见范围

- 销售人员可以新增往来单位中的客户。
- 往来单位以“所属人员”为归属依据，不以“创建人”为归属依据。
- 普通销售只能看到所属人员是自己的客户往来单位；可以新增和编辑自己名下的客户资料。创建和编辑时所属人员固定为自己，不能选择或转给其他人。
- 普通采购对供应商适用与普通销售对客户相同的规则：只能看到所属人员是自己的供应商往来单位；可以新增和编辑自己名下的供应商资料；创建和编辑时所属人员固定为自己，不能选择或转给其他人。
- 主管和老板可以指定往来单位的所属人员。销售主管可分配给销售人员，采购主管可分配给采购人员；老板可分配给所有人。

## 10. 询价、需求转报价与产品资料同步

- 询价单进入“待老板确认价格”阶段后，冻结该单的继续询价操作：不能修改该单供应商信息，也不能在该单新增供应商。老板确认阶段增加“驳回”按钮；驳回后才允许继续询价和修改供应商信息。页面与接口都应遵守这一阶段限制。
- 询价单转成报价单后，原需求单仍作为独立记录保留，但不在需求单列表页展示；报价详情页底部新增“需求单信息”栏目，在同一个详情页展示并追溯原需求单的历史数据。

- 报价成功后，老板也可以执行销售在报价单上的后续操作，例如转销售单。
- 询价转报价生成或更新产品库资料后，产品库应及时显示最新信息，避免必须等待或手动反复刷新才看得到更新。

## 14. 销售单低于成本提醒

## 19. 全系统操作按钮防重复提交

- 当前部分操作按钮点击后虽已执行相应业务动作，但仍可再次点击，后端因此收到同一动作的多次请求，可能造成重复建单或流程状态错误。需要覆盖全系统的保存、提交、审批、转换、发货及待办处理等会改变数据的操作按钮。
- 操作发起时立即锁定本次提交并显示处理中；请求尚未结束时不能重复提交。成功后保持按钮不可重复操作，直到页面展示最新业务状态或跳转完成；失败后才允许用户重试。
- 后端也要防重复：同一业务动作重复到达时不得再次创建记录或再次推进流程；建单类操作考虑幂等请求标识，状态流转类操作校验当前状态并原子执行。前端按钮禁用不能代替后端保护。
- 当前通用 `MutationActionForm` 已有 `isSubmitting` 禁用，但成功后在 `finally` 中立即解除禁用，同时路由刷新未必已完成，可能出现旧按钮再次可点的窗口；实施时应结合其他操作表单逐一核对。
- 参考：React `useFormStatus`、Next.js 表单 pending 状态、Stripe 幂等请求模式。此处仅记录解决方向，尚未实施。

状态：问题与目标已确认，尚未实施。
